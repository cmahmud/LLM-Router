# Decisions

These decisions are specific to the fork and anchored to the revisions in
[FREEBUFF_AUDIT.md](FREEBUFF_AUDIT.md). Proposed behavior is not a compatibility claim.

## D1 — Preserve the baseline and use dev

Verified both fork and upstream `release/v3.8.51` at
`3ee283bb944d6d62cc219f74317d5186942e1780`; created `dev` from that exact SHA. Latest published
semver release observed was v3.8.50; v3.8.51 is a development release branch. No upgrade is needed
to match the inspected upstream tip. Recheck upstream at future milestones; never rewrite the
baseline. GitHub MCP is used for branch/commit publication. Third-party repositories are read-only.

The user explicitly requests fork architecture/handoff documents under `docs/`. That instruction
takes precedence over inherited AGENTS.md's private `_tasks/` planning convention. No agent
instruction file or upstream workflow is changed. New implementation work uses isolated feature
worktrees based on `dev`, following the repository's canonical worktree location.

## D2 — Native modules; no bridge by default

**Selected:** native executor plus focused provider-local modules. OmniRoute already has connection
selection, cooldown/breaker logic, Chat/Responses/Anthropic conversion, catalogs and monitoring.
A sidecar would duplicate several of these and add deployment and failure boundaries on two cores.

**Alternative:** trefeon is the strongest inspected bridge reference for current session admission,
SSE/Responses handling, registry refresh and extensive tests. Its bridge mode means per-client
upstream-token handling, not automatically a safe drop-in for an OmniRoute provider. Hybrid mode
adds credential ownership/routing complexity. It also contains restriction-evasion techniques we
will not adopt. Neither its feature breadth nor a Rust implementation proves production correctness.

Revisit only after a concrete permitted-protocol blocker, benchmark or maintenance assessment
demonstrates an advantage. No CLI subprocess wrapper is planned.

## D3 — Establish permitted access before promising coding-client compatibility

Official `foreign-client-signals.ts` implements enforced downgrade signals for foreign tools and
system prompts. Reference tool remapping is explicitly designed to neutralize those signals.
This conflicts with the user's no-access-control-bypass requirement. Therefore generic premium
FreeBuff-backed coding clients are **not an established deliverable** from the currently inspected
free-mode endpoint. P0 is a feasibility gate; do not bury this risk in a final smoke test.

An authorized integration/endpoint or vendor confirmation is required to proceed with live gateway
support where these restrictions apply. A token, HTTP 200, or an answer generated by a downgrade
model is insufficient evidence. Offline lifecycle and protocol work can proceed without evasion.

## D4 — Sessions are credential-scoped; runs initially request-scoped

Reuse an owned, validated session for the same model. Serialize admission and completion per
credential, share refresh outcomes, and block switching while leased. Unknown upstream state and
foreign-instance conflicts must fail safely. Do not clone the anonymous browser session pool.

Long-lived shared runs (chenjh16/Quorinex) reduce START traffic but complicate cancellation,
concurrent step accounting, stale runs and conversation isolation. Per-request runs are easier to
prove correct; finish after consumption. Revisit run reuse only with a verified wire requirement.

## D5 — Explicit ownership, zero implicit spend, no eager rotation

The official client separates safe admission and exact-instance reuse. A lost POST response is
ambiguous; automatic POST retries can create/rotate state twice. Use zero wallet spend by default,
no takeover header, and no Desktop multi-session impersonation. Drain active work before releasing
owned sessions. Grace allows already-running work, not an extension for new requests.

Reference implementations disagree on older 404 behavior, model-switch release, eager renewal and
grace usage. The current official contract wins. Report unsupported admission routes explicitly.

## D6 — Reuse existing protocol translation; test it through the gateway

FreeBuff's existing registry is `format: openai`. Responses and Messages already enter the shared
handler. Keep provider wire format explicit and add integration tests proving the executor receives
Chat messages/tools, not unconverted Responses input. `apiFormat` in target resolution is model
metadata, not simply the incoming endpoint; this audit does not claim every Responses request is
currently routed incorrectly. Avoid broad changes to target-format resolution without a failing test.

Stateless HTTP first. Stateful IDs, hosted tools, WebSockets, reasoning and images require separate
evidence. Correct framing does not prove the upstream permits or faithfully runs the requested model.

## D7 — Official, revision-consistent catalog with atomic validation

Prefer official surface-specific root maps and model metadata to regex-only extraction of every
`new Set` in `free-agents.ts`. The latter can select helper agents, miss identifier constants and
advertise retired or unavailable models. Fetch source at one SHA; parse data without running code;
retain last-known-good on failure. Do not treat an empty validated inventory as a refresh error.

Reuse synced-model storage after inspecting its domain APIs, with a FreeBuff-specific authoritative
filter because the generic catalog keeps static rows not covered by synced data. Capability flags
represent tested behavior, not deductions from a model name.

## D8 — Existing credential storage and resilience; no second account system

Use provider connections and existing cooldown/model-lockout/breaker scopes. New provider-local
state manages sessions/runs only. Preserve retry hints and classify aborts distinctly. No broad
retry of ambiguous mutating requests and no replay after output. No unsupported refresh grant.
Existing metadata override and raw-error leakage are high-priority fixes.

## D9 — Independent implementation; preserve licenses if material is adapted

trefeon, lza6, chenjh16 and Quorinex have MIT license files; lza6's notice names Quorinex. The
official source carries Apache-2.0. The fatmuh tree has no LICENSE and its package metadata does
not establish a reusable source-code grant in this audit. Use concepts only from that project.
No third-party implementation code is copied into this milestone. Any later adaptation must retain
the actual applicable notices and record file-level provenance; generated extracts need provenance
and license review too. Do not import captured credentials or traffic dumps from references.

## D10 — P4 uses the pinned official catalog with bounded cached fallback

**Selected:** fetch the public `CodebuffAI/freebuff` source files at the single resolved commit
`a37beff7a5db909eb6db54654431bb521af7da1a`. Parse only the supported constant/object subset:
the base2 `FREEBUFF_ROOT_AGENT_ID_BY_MODEL` map, the `FREEBUFF_MODELS` surface, model metadata
and `FREEBUFF_PAUSED_FREE_MODEL_IDS`. The parser never evaluates fetched TypeScript, and it rejects
mixed revisions, unsupported expressions, incomplete mappings and conflicts atomically.

The provider keeps one in-memory immutable snapshot with a six-hour refresh interval, a ten-second
per-file timeout, a bounded source size, single-flight refresh deduplication and caller cancellation.
A valid empty eligible surface remains empty. Refresh failures retain last-known-good data for seven
days; after the stale ceiling, the generated emergency fixture is used. The fixture is pinned to the
same official revision and contains only active base2 rows, so withdrawn rows are not re-advertised.

Executor resolution reads the validated snapshot and fails unknown models cleanly; it does not scrape
the source during inference. The provider registry and `/v1/models` use the same normalized catalog.
The explicit provider model-sync route reuses OmniRoute's existing synced-model persistence for
official, empty and last-known-good snapshots, while never stamping an emergency fallback as fresh.
Capabilities are evidence-only: unknown tool, video, context and Responses support are omitted.

**Alternative:** a permanently hard-coded table, a third-party model API, regex/evaluation of arbitrary
upstream TypeScript, or remote discovery on every inference. These were rejected because they either
drift, are not authoritative, widen the trust boundary, or add latency/race risk on the 2-core VPS.
